# 实现检查

仅用于用户已要求实现的组件与页面。按改动和业务挑选检查，不给只调研任务追加开发或验收，不为微小样式修改创建完整矩阵。

## 状态与转换

| 适用情形 | 需要观察的行为 |
| --- | --- |
| 正常状态（default） | 内容、标签、主要操作和数据含义正确 |
| 指针与按下（hover、active） | 反馈不会挤动布局，触屏仍能找到必要操作 |
| 键盘焦点（focus-visible） | 焦点可见、顺序合理；弹层关闭后按该组件约定恢复焦点 |
| 选中（selected） | 焦点和选中含义分开；筛选、翻页或刷新后的选中范围符合业务规则 |
| 禁用（disabled） | 不能误触发；原因或恢复条件在需要时可理解 |
| 加载（loading） | 保持必要上下文，不重复提交；旧请求不覆盖较新的结果 |
| 空数据（empty） | 区分首次无内容和筛选无结果，提供适当的后续动作 |
| 错误（error） | 错误信息可读，重试或修正路径可用，保留应保留的输入 |
| 缺失值（null） | 与 0、空字符串、未加载保持业务语义上的区别 |
| 长内容与窄屏 | 文本、按钮和操作不重叠；按任务选择换行、滚动或可访问的完整内容入口 |

业务上不存在的状态可跳过。有关联时检查实际转换，如加载→失败→重试成功、选择→过滤→批量操作、打开→键盘操作→关闭；不要只截每个静态状态。

优先保留原生语义和现有组件的键盘约定。普通数据展示表格不因“可访问性”就改成 `role="grid"`；只有交互模式需要时再采用对应行为。必要时读取 APG 的具体模式及目标组件文档，并按项目要求验证。

## 代表性数据

从项目已有样例或明确标注的合成数据中选取与业务有关的情况：

- 最短与最长名称、多行说明、长错误文案；支持多语言时覆盖相应长度。
- 0、业务允许的负数、大值及单位/小数精度，检查对齐、截断和含义是否改变。
- 缺失值、空数组、单条结果、典型页容量与预期的大数据量。
- 产品允许的日期边界和时区展示；不把领域不允许的值当成正常数据。

观察按钮或列是否被撑开、数字是否溢出、状态切换是否使布局跳动，必要内容是否能完整读取。大数据检查采用真实预期规模，不为普通 UI 改动启动无限量压力测试或新建性能工程。

## 交付证据

使用项目已有检查方式验证相关终端和操作。只做了代码检查、只观察了截图或没有可用运行环境时，分别说明；不得把读 APG、通过静态检查或原站演示当作项目可访问性验收。

报告实际覆盖的关键状态与仍影响结论的缺口。普通实现无需交付一张空白状态清单；详细交接才记录状态→预期→实际证据。
