# 可选：常驻编程规则片段

仅当你希望 Skill 未触发时也有相同提示，才把下面片段手动合并到实际使用的 Codex/OpenCode
规则文件中。先核查已有内容，不覆盖或自动修改全局/项目配置。Worker 不自动继承 Leader 的
规则，因此首次派工仍要传递本包 `worker-rules.md`。这些是指引，不是运行时权限控制。

```markdown
## 编程四问：先判断该不该改，再决定由谁改

禁止仅为了代码简洁优雅、偿还原代码技术债或修复未被要求的疑似 BUG 而修改代码。
每个独立改动在详细设计中必须给出依据：
1. 是否属于当前需求？不属于，不改。
2. 不改是否阻塞当前需求或必要验证？不阻塞，不改。
3. 是否可以最小改造？只解决当前障碍，最小化正确改动及影响范围，避免全面重构。
4. 是否影响原有契约？必须保留 API、配置、日志、数据结构、下游依赖、用户工作流及兼容逻辑；
   不确定或有冲突，先停止相关改动。只有用户明确修订需求并授权具体变更，才能按新边界继续。
这些规则约束 Codex 直接修改、Worker、返工、Reviewer 和集成。允许修改文件不等于允许清理
文件内所有问题；评审建议不产生扩范围授权。本次引入的缺陷要修，无关旧问题不得顺手修。
```
