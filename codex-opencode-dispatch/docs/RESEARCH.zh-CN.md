# 开源派工 Skills 深度分析与 v2 设计取舍

日期：2026-09-18。目标环境不变：Codex 作为 Leader，通过 AlaeddineMessadi
`opencode-mcp@3.0.0` 调度 OpenCode 中的固定 DeepSeek Worker。

研究范围是项目的 Skill 正文、关键模板、协议文档和部分运行/验证脚本，不是对所有仓库做
完整安全审计，也不是把 README 功能宣称当作实测结果。全部链接见 [SOURCES](SOURCES.md)。

## 1. 结论

值得吸收的不是更多 Agent 数量，而是三项工程纪律：**把任务说清、把证据留准、在满足条件时停止**。

v1.1 的职责划分方向正确，但仍有几处容易实际增加成本：Codex 可能先把设计做得过细；
每次重复搜代码；Worker 完成后重复全量审核；等待超时后误重派；把旧测试对应到新修改；
多个会话虽不同，却仍共享文件或测试数据库。

v2 因此不扩建运行时，而是增加可恢复的任务身份、证据边界和精简的验收规则。

## 2. 各项目真正值得吸收的部分

### 2.1 obra/superpowers：任务闭环与上下文纪律

读到的当前版本将任务 Brief、报告、审查材料和进度台账文件化；对同类小改动做合批；
独立任务使用新上下文，修复则复用原实现者。当前 task reviewer 是一次读取、给出规格与质量
两个结论，并非必须连续启动两个 Reviewer。[S1、S2、S3]

**吸收：**新任务与返工分开管理；Brief 不包含完整聊天历史；台账防止压缩后重复派工；
默认一次审查两个维度；后续只复审修复增量。

**不照搬：**其模型分级/更换更强模型与用户固定 Worker 模型的约束冲突；每项任务都支付
完整独立审查成本也不符合小任务场景。其工作树流程中的自动提交、安装依赖或权限受限后
回到共享目录，不能作为我们并行执行的无条件默认行为。[S1、S4]

### 2.2 oubakiou/delegate-skills：把昂贵上下文留给判断

它将实现、调查、审查等分开，明确设置委派成本门槛；报告通过文件按需读取，避免把大量
读取和试错输出灌回主 Agent。协议还考虑续接、递归委派和缺失前提时停止。[D1–D4]

**吸收：**需要时才建 Scout；让 Builder 合并局部调查、实现、测试；报告先看摘要，再看
特定证据；限制递归委派；真实用量与估算值分开记录。

**不照搬：**现成多 CLI/模型路由、专用索引运行时和每类角色的不同默认模型。我们已有 MCP，
不再建立第二套调用栈；一个 Markdown 目录索引已足以支持大多数交接。

### 2.3 amElnagdy/delegate-skills：先验证测试标准，再相信测试结果

其 OpenCode 审核流程明确要求先审已有测试的修改，再看绿色结果，关注删测试、加 skip、
放松断言及“只差一点”的隐性规格变化。实现报告不是独立证明，Leader 持有最终落地权。[A1、A2]

**吸收：**将测试、fixture、snapshot、容差、CI 参数的变化作为专门审核项；把需求遗漏、
范围膨胀和局部实现错误分别处理。

**不照搬：**重新引入其 CLI relay，因为你的 MCP 已承担调用和任务管理；也不把所有旧测试
修改都视为恶意。行为确实获准变化时，应明确批准相应测试更新，而非禁止必要修改。[A3]

### 2.4 multi-agent-orchestrator-skill：先选执行结构，再拆任务

其流程区分直接、单 Worker、并行、分阶段；公共基础先处理，之后才分派叶子任务，
并记录文件所有权和依赖。同时它有独立的后台监督运行时。[H1、H2]

**吸收：**公共 API、schema、锁文件和生成代码的单一责任人；依赖图与基础版本；先完成基础
再并行；工作区之外的数据库、端口、缓存同样要隔离；恢复时使用持久化记录。

**不照搬：**自动重启监督器、第二层管理模型、额外 daemon，以及跳过权限的启动参数。
这些增加维护与安全成本，而且会与现有 MCP 生命周期竞争。

### 2.5 delegate-to-deepseek-harness：验收契约与停止条件

其核心是限定任务和验证范围，达到条件后停止额外重做，并对重复失败设置升级处理。[L1]

**吸收：**事前确定必须证明什么；验收完成后不顺手重构；两次同类修复不收敛时回到 Codex
诊断；区分运行证据和 Worker 声称完成。

**不照搬：**低风险仅凭回执完全不看 Diff。范围和测试都绿仍不能证明需求一定完整；尤其
金融计算、公共接口或权限修改，少量代码也可能高风险。

## 3. 必须辨析：思想成熟，不代表每段脚本可直接复用

例如对 LomoMao 验证脚本的静态阅读发现：文件清单来自 `git status --porcelain`，数量统计
主要来自普通 `git diff --numstat`；依赖/API 检测依赖对特定文本模式的匹配。[L2]

**由代码推导的局限：**任务若已经提交，当前工作区状态可能干净；仅普通 Diff 也不能覆盖
所有暂存变化。针对 `package.json` 或 `export` 的文本线索不能证明跨 Python/Rust/C++ 项目的
“没有新依赖”或“API 未变”。因此我们没有移植它的验证脚本。

v2 新写的可选脚本只承诺 Git 范围和快照身份：显式基线、NUL 分隔文件名、已提交/暂存/
未暂存/未跟踪覆盖、重命名两端、内容散列、submodule/异常路径提醒。它不声称自动证明
API、依赖、业务语义或测试真实性；这些仍归实际检查与 Codex 判断。

## 4. 对 v1.1 的关键修正

### 4.1 从“判断都自己做”改成“最终判断自己负责”

Codex 决定公共边界、业务定义和验收标准；Worker 可决定私有函数结构和约束内实现。
否则 Codex 先写一份接近完整代码的详细设计，Worker 只照抄，不会真正减少主要工作量。

### 4.2 不再按轻/重简单等同于同步/异步

风险、执行量和调用等待方式彼此独立。高风险的一行金融修复仍要高标准验收；耗时长但
机械明确的任务可异步执行。已知的一条测试命令不必再启动一个 LLM Worker。

### 4.3 返工优先复用 Session，但跟踪新的 Job/Message

当前 MCP 的 `run/fire` 支持已有 `sessionId`，并返回可追踪的新任务回合。
`reply` 仍可做简短续接，但不能假设它返回同样的持久化 job 结构。[M1]

### 4.4 超时、过期与取消不是一个状态

等待窗口到期不代表执行停止；提交结果不明时不可盲目重试。任务记录默认从创建起保留
24 小时，句柄过期不等于远端任务消失。取消最终影响 Session，需确认没有并行回合。[M2–M4]

### 4.5 不承诺“后台完成会自动叫醒 Codex”

这个 MCP 版本的普通工作流需要显式观察；独立 OpenCode 服务与 MCP 自己启动的子服务，
断线后的存活行为也不同。新 Skill 采用紧凑检查和受客户端超时约束的等待，不依赖虚构通知。[M3]

### 4.6 固定模型从一句约定变成可验证配置

默认值不是硬锁；不透明默认下显式传同一组已验证 ID。所有 Worker 角色都遵守固定模型，
不因任务困难自动改模型。辅助模型、agent 覆盖和实际生效元数据也需要如实记录。[M1、M2]

### 4.7 验收不再只看自报结果

测试结果关联代码快照、测试本身、命令和关键环境。自己写的 JSON/日志文件仍可能只是
Worker 声明；已有可信 CI/工具执行记录可复用，但它必须对应同一候选状态。

### 4.8 明确“不应该省”的部分

不能省掉用户明确要求的回归、关键安全/金融不变量检查、测试完整性审核和新组合状态的
集成验证。节约来自消除重复、缩小无效上下文，而不是降低质量条件。

## 5. 新工作流

| 阶段 | Codex | Worker |
|---|---|---|
| 入口 | 读项目约束与需求，确认模型/工具/目录 | 不默认启动 |
| 路由 | 选直接、单个、并行或分阶段 | 必要时回答具体调查问题 |
| 合同 | 固定公共决策、范围、可观察验收标准 | 接受独立可执行 Brief |
| 执行 | 保留轻量台账，不重复所有读取 | 局部设计、实现、测试、修普通错误 |
| 回执 | 先看结果与证据索引 | 简短回执，完整日志按需可取 |
| 验收 | 检查测试标准、风险逻辑、可信证据 | 必要时一个新上下文 Reviewer |
| 修复 | 给具体失败项，控制范围与回合 | 原 Session 修复，更新证据 |
| 集成 | 验证最终组合；有权限才提交/合并 | 不擅自提交或部署 |
| 完成 | 条件齐全即停止；如实列出未验证项 | 不自行宣布最终接受 |

## 6. 关于 token 与质量的边界

本次能直接验证的是 Skill 文件与辅助脚本，不是某个百分比的实际成本收益。
主入口变短只能说明静态文本负担减少；真正 token 取决于激活、引用加载、缓存、调用返回、
模型行为和返工次数。为了证明有效，需要用相近任务比较真实 Codex 用量，并同时记录缺陷
和回归结果，不能用一次简单任务推断所有项目收益。

同一个固定模型的两个 Worker，即使上下文独立，也可能共享相同盲点。Reviewer 是额外
证据，不能替代 Codex 对高风险逻辑的直接判断。

## 7. 实施边界

保留原 MCP 与 Harness；不搭新服务；不自动修改用户项目/密钥/模型配置；不默认扩大权限。
Skill 主文只保留必须执行的规则，细节按需加载。额外脚本是可选、只读、无第三方依赖的
范围工具，不演变为另一套 Agent Runtime。

这套优化的目标是：**Codex 少做重复劳动，不少负最终责任。**
