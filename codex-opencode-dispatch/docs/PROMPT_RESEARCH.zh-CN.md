# Leader–Worker 提示词规范研究与 v2.1 优化

研究日期：2026-09-18。目标环境：Codex → AlaeddineMessadi `opencode-mcp@3.0.0`
→ OpenCode → 操作者固定的 Worker 模型。

本次研究不是寻找一段“万能提示词”，而是确定：**主控给什么、执行者能决定什么、
结果如何证明、发生问题怎么继续，以及什么时候结束。** 这里只引用第一方技术文档和
开源项目源文件；不使用 Star 数、宣传评级或未核验的节省比例衡量效果。

## 1. 调研结论：应规范通信语义，不应机械限定七个标题

Anthropic 的多 Agent 工程经验把目标、输出形式、工具/来源提示和任务边界作为委派要素，
同时提醒并行化有额外成本。上下文工程文章强调信息应精简但充分，不宜走向空泛指令或
脆弱的逐步硬编码。[P1][P2]

因此，我们采用“语义必须完整，表达按任务缩放”：微小已知修改直接做；值得委派的小任务
使用紧凑契约；高风险、多人并行或重型工作使用完整版。既不把一句“帮我改好”当规格，
也不为了格式给每次派工塞上千字。

OpenAI Agents SDK 区分由 Manager 保留控制权的工具式代理调用，以及将对话控制转交给
其他代理的 handoff。我们的 Worker 是前一种协作关系：帮助完成子任务，不接管用户会话
或最终验收。[P3]

MCP 的 Prompts 规范定义提示模板如何发现和获取；它不替项目制定代码验收、资源所有权
或业务决策规则。[P4] **`ocw/1` 是本包自定义的任务内容约定，不是行业统一标准，也不是
给现有 MCP 增加的参数或接口。**

## 3. 最值得新增的七项规范

### 3.1 分层：通用规则、任务契约、增量消息

以前每次都重新写一套角色说明、禁令和输出格式，既重复，也容易产生细微矛盾。
新版把稳定部分放在 `templates/worker-rules.md`，按角色提供具体 brief；返工只发 delta。

但不能假定 OpenCode 自动继承 Codex 的全局 Skill。新 Session 必须收到规则正文，或成功
读取服务器端可访问的规则文件。普通任务无需额外发一轮“确认收到”；Worker 在真正改动
前核对身份、基线和授权，发现不一致才返回阻塞。

这不是通过删掉信息来省 Token，而是避免重复生成和传播同一套信息。稳定前缀是否命中
缓存、缓存能节省多少，仍需实际服务端计量，不能由文件布局推断。

### 3.2 单一权威规格：区分事实、假设、决定

契约应明确三类内容：

- **事实：**“函数在这个路径，现有调用者是这些”，附来源。
- **假设：**“可能因为 bool 属于 int 而误放行”，必须验证，不是结论。
- **决定：**“本次规定 bool 必须拒绝”，属于已授权的正确性要求。

数值、单位、函数签名、错误类型、NaN/null 规则和兼容边界只维护一个权威版本。
外层 dispatch 只指向它，不另外写一个容易失真的长摘要。

Superpowers 当前正文也强调将精确值留在任务 brief，而不是把完整计划或历史重贴给新执行者。[P5]
我们的补充是：Worker 读不到该文件时必须复制必要内容或阻塞，不能为了“精简”引用不存在的共享上下文。

### 3.3 自主权不是非黑即白

“Codex 做所有设计，Worker 只执行”容易使 Codex 先完成一遍实现工作。新版明确：

**固定的决定**包括业务含义、公共契约、安全与兼容性；**自由的决定**包括约束内的私有
helper、局部算法和代码组织；**升级的决定**是跨越约定边界的改动。

增加 Designer 模板，用于收集决策所需证据和提出有限方案。它不能因为写的是“方案”就
代替 Codex 批准 API 变更；也不要求 Worker 对每个变量名都询问主控。

### 3.4 AC → 检查 → 实际证据的闭环

仅有“测试通过”不足以解释实现满足了什么。新版使用关联 ID：

```text
AC-2：明确 bool 输入必须拒绝
V-1 → AC-1, AC-2：指定测试或检查方法
F-1 → AC-2：审核发现该输入仍被接受
```

同一检查可以覆盖多个 AC，设计任务也可以使用源码证据和可审查的方案，而不是强行制造
可执行测试。不存在的检查命令不得凭空填写；允许在约定范围发现项目现有命令。

必须区分“预计执行”“Worker 声称执行”“可信执行结果”“源码语义得到支持”。结构化
输出只让信息易处理，不使它自动可信。原有测试被删、skip 增多或容差被放宽时，先审这些
变化再解释绿色结果；amElnagdy 的审核规则特别强调这一点。[P7]

### 3.5 身份、基线和依赖必须可对齐

任务内容增加 `Task / Revision / Attempt / Role / Workspace / Snapshot`。
这不是要求所有调用都维护数据库，而是让重任务、返工和多 Worker 不把不同版本的结果混在一起。

- 同一个缺陷返工：契约 Revision 不变，Attempt 递增。
- 需求含义变化：新 Revision，明确替代关系，停止受影响的旧工作。
- 报告来自旧版本：先关联和核对，不直接接受，也不直接重复派工。
- 并行依赖：读取已确定版本的接口或产物，不读取另一个 Worker 正在修改的工作树。

身份字符串不提供服务端幂等性；提示“停止”也不等于真正取消进程。它们需要现有 MCP
返回标识、任务状态和实际取消机制配合。

### 3.6 返工是精准修复，不是无限重做

单独提供 Rework 和 Clarification 模板。返工内容只有：父契约、失败条件、事实证据、
修复边界、不可改变的不变量、受影响的检查和回传格式。要求说明“哪个标准未满足”，
而不是“感觉不够好，重新做一遍”。

若只是报告缺少位置，不应重新实施功能；补证据即可。若需要改动需求，不能伪装成普通
返工。连续两次同类修复不收敛时，Codex 应诊断错误任务分解、上下文缺失或实现问题。

### 3.7 规范不要求暴露内部思考，也不强迫形式化成功

提示词要求输出短的理由、证据、风险和决策请求，不要求隐含思维链或全过程自述。
审核者不设“必须找到三个问题”的配额；Worker 不接受“无论如何不准停，直到全部变绿”的命令。

允许 `needs_context / blocked / partial`，但这些不能被当成验收成功。紧凑摘要不得隐藏
失败、缺失检查或不确定性。非阻塞的额外美化建议留作后续，不拖延本任务的可验证结束。

## 4. 为什么安全规则必须独立于提示格式

OpenAI 的 agent safety 文档建议不把不可信数据放入高优先级指令，并用明确的数据结构和
实际安全措施限制数据流；同时说明这些措施不能彻底消除注入风险。[P8]

因此：Worker 不得把源文件注释、Issue、日志或另一个 Worker 的报告当成改模型、发密钥、
扩大写入或放行权限的指令。授权过的项目规则仍然需要遵守；内容冲突则停止并报告。

OpenCode 的 permission 配置是运行时能力；Skill 中的 `Write: none` 是任务契约。[P9]
两者不能互相冒充。仅靠 deny 若干 Shell 字符串也不是完整安全沙箱。对不可信工作应使用
适当的运行时/操作系统隔离，并另外隔离数据库、端口、缓存与凭据。

## 5. 对已安装 MCP 的实际落地

v3.0.0 的 `opencode_fire` 接受 `prompt`，可带 `sessionId`、模型和 agent 等字段；
`directory` 是服务器端目录。任务语义放进 `prompt`，不能凭模板新增 JSON 参数。
`opencode_ask` 的可选 `system` 不应被误传给未提供该字段的 `opencode_fire`。[P10]

因此没有修改 MCP，不要求换工具，不自动安装别的模型。正常任务仍用 run/fire；
返工延续原 Session 并保存新的 job/message 标识；等待超时照旧按观察窗口处理。
`agent=scout` 也不能因为模板有这个角色就直接发送，必须先有真实对应的 OpenCode agent。

## 6. 新增的确定性检查及其边界

`scripts/prompt_contract.py` 可以检查：元数据、角色/模式、模板残留、绝对目录的语法、
明确快照标识、必需章节、只读角色声明、AC 与 V/F 引用、重复 ID，以及带父契约的
返工身份一致性。可将通用规则与已填写 brief 组装为一个新文件，默认不覆盖已有文件。

它不执行提示词中的命令，不连接网络或 MCP，不打开提示词引用的源码文件。
**它不验证远端路径存在、代码 SHA 真实、实际模型、语义完整性、授权、恶意内容或测试真伪。**

只有规范格式可被确定性检查；业务是否足够清楚仍需 Codex 判断。把 lint 通过称为“安全
派工”或“结果质量保证”会构成新的误导。

## 7. 应如何验证真正有效

采用旧版 v2.0.0 与 v2.1.0 的相同任务配对：同仓库/基线、同模型和权限、同验收目标。
覆盖轻型、中型、跨模块、调查、方案、并行、返工、丢响应、缺环境与提示注入场景。

评价最终行为和正确状态，而不是要求模型按唯一工具序列运行。Anthropic 的 Agent eval
指南区分任务执行轨迹与最终结果，并讨论工具执行环境和评判方法的重要性。[P11]

至少记录：Codex 与 Worker 的真实 Token、总耗时、首次验收率、遗漏缺陷、越界修改、
重复派工、返工次数、证据读取量。不能获得 Token 时填 null，字符数另列。先守住权限和
正确性底线，再比较成本；不能用低质量“完成更多任务”抬高指标。

本包实际做了确定性脚本和结构测试，尚未运行用户环境中的 Agent 行为实验。没有任何
实测节省比例、模型遵循率或端到端通过率的承诺。
