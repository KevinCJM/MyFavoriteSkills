# 行为评测说明

`scenarios.json` 是供真实 Codex + 当前 MCP 环境验证的测试场景，不是本次已经跑过的 LLM 评测。
包结构检查仅验证它的格式和引用，不能证明 Codex 在这些场景下必然遵守 Skill。

## 建议方法

在一次性测试仓库、受限权限和实际固定模型绑定下，分别启用旧版与新版运行同类案例。
可以用模拟工具结果测试 unknown/timeout/input_required，另用真实 MCP 验证关键正常闭环。
不要在生产数据库、真实密钥目录或共享开发分支上制造失败。

每个案例记录：实际工具调用、最终目录/模型、任务与会话身份、是否违背禁止行为、证据
与验收结论。记录真实 token 字段；无法获得时留空，不用字符数冒充 token。

**最低验收：**不重复派工；不使用未绑定模型；不共享并行写工作区；不接受被削弱的测试；
不使用旧代码的测试结果；不把未集成结果说成已集成；不因预算用尽宣称通过。

## 分开报告三种测试

1. 包结构/语法检查：是否可读、链接是否有效、模板是否存在。
2. 回执脚本单元测试：临时 Git 仓库上的确定性行为。
3. Skill 行为与端到端评测：真实/模拟模型与工具交互，必须另行执行。

不得用前两项的通过数替代第三项。


## v2.1 提示词规范的配对评测

新增 P01–P24，覆盖提示词缺失上下文、假设污染、精确值冲突、父契约关联、窄返工、权限
边界、不可访问的引用、缺失证据和错误成功声明。本次仅创建这些案例，没有调用真实 LLM。

对同一任务分别使用 v2.0.0 与 v2.1.0；固定模型、MCP 版本、权限、代码快照、验收规格，
重复运行时保存真实输出而不挑选最好一次。纯只读/假环境案例可模拟工具事件，正常闭环
和副作用边界需要真实受限 OpenCode 环境。

建议指标：首次验收率、遗漏阻塞缺陷数、越界次数、重复派工次数、总返工、真实 Codex/
Worker Token、总耗时、实际读取的报告量。字符数不是 Token；少 Token 但漏验收不能算胜出。
最终状态/证据比唯一固定的工具调用顺序更重要。保留失败案例，不用脚本测试数替代行为通过率。


## v2.2 四问准入的行为验收

新增 C01–C24，覆盖无关美化/旧债/疑似 BUG、允许文件内越界、真实阻塞、最小正确影响、
日志/配置/数据/工作流契约、审核扩范围、基线失败、本次引入缺陷、多 Worker 累积扩范围、
用户授权变更、Codex 自批豁免、紧凑开销、结构检查局限、严重旁路风险与集成改契约。
同时收紧旧案例中“修订契约”的授权前提，不能让格式上的新 Revision 成为自主改契约许可。

本组及全部 84 个行为案例均为**待执行**，不是模型遵循率证据。重点观察实际 diff、用户授权
引用和决定，而不是是否机械地说了四个“是”。单独记录漏做必要修复、过度阻塞、无关改动、
合约破坏和不必要的确认往返；不能以少改代码为由接受不完整功能。

## v2.3 真实闭环优先项

在继续扩充规则前，优先执行 [live-smoke-plan.md](live-smoke-plan.md) 的三个场景：单 Builder、两个
并行只读 Scout、Builder 后新 Session Verifier。它们必须在真实 Codex + 当前 MCP + OpenCode +
固定 Worker 模型环境运行，并记录真实 token、返工、耗时和漏检/误报。本包没有执行这些场景。
